# Agent Note: 按固件系统保存首次启动脚本草稿

Status: implemented

## Problem

双系统选择器原本始终读取同一个 setup.sh，并在切换发行版时保留同一编辑框内容。用户确认 OpenWrt 与 ImmortalWrt 应分别使用对应模板和草稿，而同一 ImmortalWrt 的官方与 KyaruCloud 后端应共用草稿。将发行版名称替换进用户命令，或让迟到的模板响应写入另一系统，会破坏这一约定。

## Decision

`www/js/uci-defaults.js` 独立负责示例加载和草稿状态；`main.js` 在服务切换时通知它当前 distribution。草稿以 distribution 为键保留在当前页面内存，空草稿也保留；按服务 id 存草稿会使同一系统切后端丢失上下文，因此不采用。刷新页面后状态清空。

编辑器初始为空。用户显式点击“插入当前系统示例”才读取 `config.uci_defaults_templates` 中的地址，未配置时兼容原按钮的 data-link。OpenWrt 保留 setup.sh，ImmortalWrt 使用独立的 immortalwrt.sh；两份示例保持各自内容，不对用户草稿执行名称或命令替换。插入时保留原文并补必要的换行，完全相同的示例已经存在时不重复插入，也不再沿用原来的点击删除行为。

模板请求记录选择代次、编辑代次与发起时原文。等待期间切系统（包括切走又切回）或编辑（包括撤销到原文）使结果作废。同系统更换后端不使请求作废。请求期间禁用插入按钮；加载失败保留草稿，当前请求结束后允许重试，旧系统的错误不覆盖当前界面。

## Evidence and related notes

- ImmortalWrt 示例来自选择器仓库 `30c511175ba8f9cbdbd21bf1bb565c98bc25a01b` 的 `www/uci-defaults/setup.sh`；本次固定为本地文件，执行逻辑与现有 OpenWrt 示例一致，Wi-Fi 名称示例不同。两个示例均保留按版本设置 LAN 地址格式的说明。
- 活跃笔记检索：与[服务选择](2026-10-30-asu-service-selection.md)部分重叠，本篇接管其中“跨系统共用脚本”的行为并双向链接；[高级构建选项](2026-10-30-asu-build-options.md)保留软件源、公钥及请求表单的独立规则，无需迁移或归档。

## Alternatives considered

- 切系统直接替换编辑器为模板：最容易让界面立即显示对应示例，但会覆盖用户命令和有意清空的草稿。保留显式插入，并单独保存每个系统的编辑内容。
- 按后端保存草稿：与服务选择 id 完全一致，但官方与 KyaruCloud 都构建 ImmortalWrt，用户明确要求它们共用草稿。
- 在共用模板或草稿中动态替换发行版名称：能减少两份小脚本的重复，但让独立模板难以跟进上游，还可能改动用户命令；保留两份可审阅的示例，只切换加载地址。
- 把草稿保存到 localStorage：能跨刷新恢复，但会让可能含密码的脚本长期落盘，且超出本次页面切换保留的需求。当前仅使用内存。

- 浏览器加载两份实际本地模板并编辑不同脚本，三个 ASU 的模拟 POST 中 defaults 均与当前草稿完全一致。跨系统往返、同系统换后端、延迟响应遇到切系统或编辑、刷新清空、中英文、375px 布局通过，无 pageerror。未发送真实构建请求，真实固件中的脚本执行不属于本次前端状态验证。
- 原有源码风格、笔记门禁与 diff 检查通过。默认 ESLint 和 Prettier 的配置冲突由[默认检查配置](../process/2026-10-30-default-checks.md)接管并修复，当前使用 `npm run check`，不再需要替代配置参数。

## Consequences

用户能分别编辑两套配置并切换回来继续使用，首次启动命令仍由用户控制。代价是需要维护两份模板和一个小型异步状态模块。distribution 名称是草稿与模板的共同键，部署时需与服务配置保持一致。示例不能自动保证插件、设备接口或跨版本配置兼容。

草稿只在当前页面有效，离开或刷新后清空；页面说明此范围。请求发送时只提交当前显示的草稿，已提交任务继续使用原快照。后续若要求跨会话保存，应单独讨论保存范围与清除方式。
