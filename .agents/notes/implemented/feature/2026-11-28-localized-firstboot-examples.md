# Agent Note: 首次启动示例沿用官方结构并翻译运行日志

Status: implemented

## Problem

旧模板只翻译注释，中文用户在设备上看到的状态和错误仍是英文。OpenWrt 和 ImmortalWrt 的功能也不一致。用户希望沿用两边官方示例的变量区和四个配置段，直接读懂并修改，而不是引入一套新的配置开关。

## Decision

两种发行版各提供独立可复制的中英文脚本。简中和繁中共用用户的中文稿，其余界面使用英文；注释、日志和错误随稿件翻译，变量、命令和实际 UCI 值不翻译。标题、示例 SSID 和 syslog 标签区分系统。用户点击插入时才选模板，不重写草稿，不改变 ASU 请求。

默认保留网络和凭据；存在对应配置时选用简体中文 LuCI 和上海时区，Argon 静态目录存在才切换，不安装包。LAN 示例 `192.168.10.1` 和 `192.168.10.1/24` 两行都注释，启用时按版本选择一行并确认与现有网络无冲突；模板检查 IPv4/CIDR，只有 CIDR 才移除已有掩码。原先使用子 shell 隔离日志和退出；这项策略由[首次启动示例按顶层脚本执行](../simplification/2026-11-28-top-level-firstboot.md)取代。配置写入失败返回非零；没有无线硬件或无线口令长度不适用则跳过无线。

本篇取代[按系统保存脚本草稿](2026-10-30-uci-defaults-drafts.md)的“仅翻译注释”限制，以及[旧 ImmortalWrt 模板](2026-11-03-immortalwrt-firstboot-example.md)的“所有功能默认关闭”；两篇分别保留页面草稿契约和构建源/设备源的边界。[构建选项](2026-10-30-asu-build-options.md)不涉及模板执行策略。未发现需退回或删除的提案。

## Alternatives considered

- 只翻译注释可直接比较全部执行行，但实际发生错误时，用户仍看不到对应语言的提示。
- 用私有 UCI 暂存区、多个语言/主题开关或按界面推断设备语言，可提供更多策略，但偏离用户审阅的官方样式，也会让两份译本产生不同的设备配置。

## Verification

真实文件的插入测试比较简中、繁中、英文及德语回退；对译本保留命令、示例赋值及日志内插变量进行比对。Shell 回归用模拟的路由器命令检查四份模板的默认生效项、日志标签和成功/错误语言，并覆盖占位符、网络和凭据边界。`npm run check` 的 185 项 JS 测试和 7 组 Shell 回归通过。未向构建服务提交脚本，也未验证实际刷机。

## Consequences

语言只决定用户看到的文字。英文模板同样会设定简体中文 LuCI 和上海时区；不希望启用时可删改末尾对应段落。静态模板可直接编辑与分发，代价是必须同时维护四份脚本；回归测试防止翻译时改动配置命令。
