# 使用 Wrt Selector

[English](../en/usage.md) · [返回首页](../../README.zh-CN.md)

## 选择并下载固件

1. 打开[在线网站](https://addgm.github.io/wrt-selector/)。
2. 先选择**固件系统**，再选择该系统的**构建服务**。
3. 选择版本，搜索设备，并从候选列表中选中匹配型号。
4. 核对型号、目标平台和版本，结合下载说明及设备安装文档选择正确的镜像类型。

页面中的固件来源和“全部下载”链接跟随当前服务。版本和设备列表来自对应源的元数据；列表中存在某个版本，不代表构建服务器此刻一定能够构建。

| 系统 | 构建服务 | 配置的根文件系统范围 |
| --- | --- | --- |
| OpenWrt | `sysupgrade.openwrt.org` | 1–1024 MiB |
| ImmortalWrt | `sysupgrade.immortalwrt.org` | 1–4096 MiB |
| ImmortalWrt | `sysupgrade.kyarucloud.moe` | 1–4096 MiB |

这些范围是部署配置，不是实时能力探测结果。两项 ImmortalWrt 服务都使用 ImmortalWrt 元数据，当前配置不支持用它们构建 OpenWrt 修订版本。

## 定制固件

选中设备后展开定制区域，检查预填的软件包并按需编辑。展开**高级构建选项**可以设置：

- **根文件系统大小**：留空采用设备默认值；手动填写时必须是显示范围内的整数。这会在目标支持时调整 ImageBuilder 根分区大小，不会增加设备的物理存储。
- **自定义软件源**：每行填写唯一名称和 HTTP(S) 仓库地址。根据包管理器的要求，可以是 opkg 软件源目录或 `packages.adb` 这样的 APK 索引，请以所选服务要求为准。完全空白的行会忽略；填写不完整、重名或地址无效时会阻止提交。
- **软件源模式**：**追加**保留 ImageBuilder 原有软件源；**替换**只使用你填写的软件源，需要自行覆盖所选软件包的全部依赖。
- **软件源签名公钥**：每项填写一份完整公钥并保留换行。这是软件包验签公钥，不是 HTTPS 证书或私钥；密钥格式和软件源策略由服务器检查。

点击**请求构建**后，所选 ASU 服务器会收到软件包、构建选项、自定义软件源公钥和当前首次启动脚本。固件由该外部服务构建，本网站提供操作界面。

构建期间会锁定系统、服务、版本和设备选择。请求、状态轮询和结果下载始终绑定提交时的服务与设备；刷写前请核对返回镜像的信息。

## 首次启动脚本

编辑器初始为空。点击**插入当前系统示例**会追加对应系统的示例，不会重写已有命令，也不会重复插入同一示例。请根据设备和已安装软件包检查示例设置。

两套内置示例的注释都按插入时的界面语言选择：简体中文（`zh-cn`）和繁体中文（`zh-tw`）共用同一份中文注释，其他语言显示英文。执行命令、示例值和运行日志保持一致。切换语言会保留已有草稿，并取消尚未完成的插入。如需换成另一种语言，请先删除原示例再插入；此前加载的任一语言完整示例仍在草稿中时，不会再次追加。

脚本会放入镜像的 `/etc/uci-defaults/`。返回成功的脚本会被移除，返回非零状态的脚本可在后续启动时再次执行，机制见 [OpenWrt UCI defaults 文档](https://openwrt.org/docs/guide-developer/uci-defaults)。

### ImmortalWrt 示例

[ImmortalWrt 中文模板](../../www/uci-defaults/immortalwrt.zh-cn.sh)默认将所有设置注释掉，只需取消需要项的注释并编辑：

| 变量 | 行为 |
| --- | --- |
| `root_password` | 设置 root 密码，留空保持原值 |
| `lan_ip_address` | 设置 IPv4 地址；CIDR 会移除已有旧掩码，裸地址保留原掩码。25.12 及之后请使用 CIDR |
| `wlan_name`、`wlan_password` | 第一张无线网卡和接口存在时配置它们；SSID 最多 32 字节，密码 8–63 字节 |
| `pppoe_username`、`pppoe_password` | 两项都填写时，将现有 WAN 配置为 PPPoE |
| `luci_language`、`use_argon` | 可选设置 LuCI 语言；`use_argon="1"` 仅在 Argon 已安装时切换主题 |
| `system_zonename`、`system_timezone` | 两项一起设置，例如 `Asia/Shanghai` 和 `CST-8` |

无无线网卡的设备不需要填写 Wi-Fi 变量。LuCI 语言和主题合并提交，未安装 LuCI 或 Argon 时跳过对应可选设置。模板不安装主题、不访问软件源，也不重启服务。请求的设置失败时返回非零状态；日志在子 shell 中处理，不影响后续自定义命令的输出。继续追加其他命令时，需要保留希望整个脚本返回的失败状态。

日志写入仅所有者可读写的 `/tmp/setup.log`，系统日志只记录固定状态消息，不打印凭证。只读镜像与 overlay 组合下，成功执行会在 overlay 中隐藏脚本，原件仍在 `/rom`，恢复出厂设置可能再次执行。填写的密码会包含在固件中并提交给构建服务，建议首次登录后再设置凭证。

通用模板不预置 Cooluc 或其他第三方软件源。构建阶段软件源与设备运行时软件源用途不同，详见[配置指南](configuration.md#构建阶段与设备运行时的软件源)。

### 草稿生命周期

草稿只保留在当前页面内：

| 操作 | 行为 |
| --- | --- |
| 切换 OpenWrt ↔ ImmortalWrt | 分系统保存、恢复各自草稿 |
| 切换两个 ImmortalWrt 服务 | 继续使用同一份 ImmortalWrt 草稿 |
| 刷新或离开页面 | 清空全部草稿 |
| 分享选择链接 | 分享设备、版本和服务，不包含脚本草稿 |

加载示例期间继续编辑时，迟到的示例不会覆盖新编辑。已经提交的构建使用提交时的草稿快照。

## 切换服务与分享

切换系统或服务会重新加载目录并清空已选设备。重新选中设备后，软件包按该设备和服务重新预填。高级选项的编辑值仍会保留，需要再次检查软件源兼容性和大小限制。

选择链接包含 `asu=<服务ID>`。历史上的 `asu=immortalwrt` 对应 **KyaruCloud**，`asu=immortalwrt-official` 对应 **ImmortalWrt 官方服务**。保留这些 ID 是为了兼容旧分享链接，它们与 GitHub 仓库名称无关。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 找不到设备或版本 | 核对系统和服务，再检查对应固件源 |
| 目录请求失败 | 查看显示的 URL 和 HTTP 状态；元数据读取对瞬时错误重试一次，构建提交不会自动重试 |
| 自定义软件源被拒绝 | 检查软件包、架构兼容性及后端当前允许列表 |
| 切换服务后大小无效 | 调整到新范围内，或留空使用默认值 |
| 刷新后草稿消失 | 草稿不写入浏览器存储，需要长期保留时请另行保存 |
| 缺少 `device_packages.json` | 这是可选的部署文件，未配置不影响正常使用 |

网站问题请提交到 [Wrt Selector Issues](https://github.com/ADDGM/wrt-selector/issues)，附上服务、设备、版本、错误信息和复现步骤，并移除凭证及脚本中的隐私内容。
